# Настройка app-ads.txt для AdMob

AdMob просит разместить файл **app-ads.txt** на вашем **сайте разработчика**, чтобы подтвердить, что вы владелец приложения и разрешаете показ рекламы. Файл не кладётся в приложение — только на веб-сайт.

---

## Что сделать по шагам

### 1. Определить свой «сайт разработчика»

Это тот домен, который вы указываете в **App Store Connect** как:
- **Support URL** (URL поддержки), или  
- **Marketing URL** (маркетинговый URL), или  
- любой ваш постоянный сайт (лендинг, личная страница, блог).

Примеры: `https://yourname.com`, `https://myapp.github.io`, `https://yourcompany.com`.

Если сайта пока нет — его нужно завести (хостинг, GitHub Pages, любой бесплатный хостинг с вашим доменом).

### 2. Создать файл app-ads.txt

Создайте текстовый файл с именем **ровно** `app-ads.txt` (латиница, без пробелов).

**Внутри файла — одна строка (без решёток и комментариев):**

```
google.com, pub-7269040792290642, DIRECT, f08c47fec0942fa0
```

Это строка, которую дал вам AdMob. Менять её не нужно.

### 3. Опубликовать файл в корне сайта

Файл должен открываться по адресу:

**https://ВАШ_ДОМЕН/app-ads.txt**

То есть файл лежит в **корне** сайта (не в папке типа /docs или /files).

Примеры:
- Сайт `https://example.com` → файл по адресу `https://example.com/app-ads.txt`
- Сайт `https://mysite.github.io` → файл по адресу `https://mysite.github.io/app-ads.txt`

**Как разместить:**
- Обычный хостинг: загрузите `app-ads.txt` в корневую папку сайта (рядом с index.html или корнем домена).
- GitHub Pages: положите `app-ads.txt` в корень репозитория (или папки, из которой идёт публикация).
- Конструкторы сайтов: найдите раздел «Файлы» / «Медиа» и загрузите файл в корень, либо создайте страницу с таким URL, если конструктор так умеет.

### 4. Проверить

1. Откройте в браузере: **https://ВАШ_ДОМЕН/app-ads.txt**
2. Должна отображаться одна строка:  
   `google.com, pub-7269040792290642, DIRECT, f08c47fec0942fa0`
3. В AdMob обновление может занять от нескольких часов до 1–2 дней — после этого предупреждение должно пропасть.

---

## Важно

- Имя файла — **именно** `app-ads.txt` (нижний регистр).
- Файл должен быть в **корне** домена, а не в подпапке.
- В самом файле — только строка от AdMob, без лишнего текста в начале строки (можно оставить пустые строки или комментарии после неё по спецификации IAB).
- Если позже AdMob даст другую строку (например, другой publisher ID) — замените строку в файле на новую.

Готовый пример содержимого файла лежит в проекте: **Docs/app-ads.txt** — скопируйте оттуда строку (без решётки) и вставьте в свой `app-ads.txt` на сайте.

## Если Google не находит app-ads.txt (диагностика)

По [инструкции AdMob](https://support.google.com/admob/answer/9776740) часто мешают два момента.

### A. robots.txt блокирует краулер

Краулер Google для app-ads.txt подчиняется файлу **robots.txt** на вашем сайте. Если в нём есть жёсткие правила (например, `Disallow: /`), доступ к `app-ads.txt` может быть запрещён.

**Что сделать:**

1. Убедитесь, что на сайте есть файл **robots.txt** в корне: `https://ВАШ_ДОМЕН/robots.txt`.
2. Добавьте в **robots.txt** блок, разрешающий краулеру app-ads.txt доступ:

```
User-agent: Google-adstxt
Disallow:

User-agent: Mediapartners-Google
Disallow:
```

Если файла robots.txt не было — создайте его в корне сайта (рядом с app-ads.txt) с этим содержимым. Можно добавить и другие правила для остальных ботов выше или ниже этого блока.

**Проверка:** откройте `https://ВАШ_ДОМЕН/robots.txt` в браузере и убедитесь, что блок `Google-adstxt` есть и без опечаток.

Готовый пример: **Docs/robots.txt** (положите его в корень сайта вместе с app-ads.txt).

---

### B. Краулер заходит по «неправильному» URL

AdMob определяет домен по **сайту разработчика** из карточки приложения в App Store. Краулер может обращаться к поддомену (например, `www.flags.worldarena.games` или `m.flags.worldarena.games`) или к другому домену, если в сторе указан другой URL.

**Что сделать:**

1. В AdMob: **Apps** → **View all apps** → вкладка **app-ads.txt**. Откройте детальный статус по вашему приложению — там указан **точный URL**, по которому краулер ищет файл.
2. Проверьте в браузере этот URL: `https://ТОЧНО_ТОТ_АДРЕС/app-ads.txt` — файл должен открываться и показывать вашу строку.
3. Если у вас несколько доменов/поддоменов:
   - Либо разместите **app-ads.txt** на том же хосте, по которому краулер заходит (в корень того сайта).
   - Либо настройте **редирект** с того URL, который краулер использует, на страницу, где лежит app-ads.txt (один домен/поддомен — источник истины).

**В App Store Connect** проверьте, какой именно **Developer Website / Support URL** указан для приложения — краулер идёт именно по нему. URL должен быть рабочим и вести на тот сайт, в корне которого лежит app-ads.txt (и при необходимости разрешающий robots.txt).

---

### C. «We couldn't verify» / Check for updates не помогает

Если кнопка **Check for updates** в AdMob не верифицирует приложение, пройдите по шагам:

1. **Узнать URL, который проверяет AdMob**  
   В AdMob: **Apps** → **View all apps** → вкладка **app-ads.txt**. Откройте приложение **World Arena: Flag Quiz 225+ (iOS)** и посмотрите детальный статус — там должен быть указан **URL, по которому краулер ищет файл** (например `https://worldarena.games/app-ads.txt` или с www). Откройте этот URL в браузере — должна открываться одна строка с `google.com, pub-..., DIRECT, ...`. Если по этому URL файла нет или другой контент — добавьте app-ads.txt в корень именно этого хоста или настройте редирект.

2. **Совпадение с App Store**  
   В **App Store Connect** → ваше приложение → **Информация о приложении** (App Information) → **URL-адрес службы поддержки**. Домен в этом URL должен быть тем же, в корне которого лежит app-ads.txt. Рекомендуется указать без лишнего пути, например: `https://worldarena.games` (нижний регистр часто надёжнее для краулеров). Сохраните, подождите распространения в сторе (до 24 ч), затем снова нажмите **Check for updates** в AdMob.

3. **Приложение связано с магазином в AdMob**  
   В AdMob в карточке приложения проверьте, что приложение **привязано к App Store** (есть ссылка на приложение в App Store). Если приложение добавлено вручную без связи со стором, верификация app-ads.txt может не проходить. При необходимости заново добавьте приложение через «Link to app store» и укажите ссылку на приложение в App Store.

4. **Формат файла**  
   В файле app-ads.txt — одна строка, без BOM и лишних символов в начале:  
   `google.com, pub-7269040792290642, DIRECT, f08c47fec0942fa0`  
   Должно быть именно `google.com`, не `admob.com`. Publisher ID (`pub-7269040792290642`) — тот, что в вашем аккаунте AdMob.

5. **Подождать после изменений**  
   После смены URL в App Store или правок на сайте подождите **24–48 часов** и снова нажмите **Check for updates**. Краулер обходит не мгновенно.

Если после этого верификация не проходит — в том же экране AdMob (детальный статус app-ads.txt) часто показывается причина (например «File not found» или «Wrong domain»). Эту фразу можно ввести в [справку AdMob](https://support.google.com/admob/answer/9776740) или обратиться в поддержку AdMob с указанием точного URL, по которому вы проверяете файл.

### Проверка из терминала

Убедиться, что файл доступен по URL:

```bash
curl -s https://ваш-домен.com/app-ads.txt
```

Должна вывестись строка: `google.com, pub-7269040792290642, DIRECT, f08c47fec0942fa0`

Проверить robots.txt (чтобы краулер app-ads.txt не блокировался):

```bash
curl -s https://ваш-домен.com/robots.txt
```

В выводе должен быть блок `User-agent: Google-adstxt` и строка `Disallow:` (пустой запрет = всё разрешено).
